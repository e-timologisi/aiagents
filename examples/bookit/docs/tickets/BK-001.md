# BK-001 — Customer books a free slot

> Fictional example. In a real project this is a GitHub issue created from the `feature.yml` form.

Labels: `ready-for-agent`, `area:domain`
Requirements: R-001   Decisions: ADR 0001 (no payment step)

## Goal
A customer picks a service, a stylist and a free start time and gets a confirmed booking.

## Affected repos
`bookit` (single repo, standalone). Change order: database migration → booking API → booking page.

## Acceptance criteria
1. Free slots for a stylist and service are computed from opening hours, service duration and existing bookings, in 15-minute steps.
2. Booking a free slot creates a booking and shows a confirmation with date, time, service and stylist.
3. Booking a slot that overlaps an existing booking of the same stylist is rejected (also when two customers submit at the same moment); the customer sees "This time was just taken".
4. Slots outside opening hours or in the past are never offered and are rejected if submitted directly.
5. A customer can only see their own bookings; requesting another customer's booking returns "not found".
6. No payment step exists in the flow (ADR 0001).

## Out of scope
Cancellation (R-002), reminders (R-003), stylist schedule view (R-005).

## Docs to update
`README.md` (how to run locally), `GLOSSARY.md` (term "slot").

## Risks
Race condition on concurrent bookings — enforce non-overlap in the database, not only in code.

## Definition of ready check
All fields filled; one repo; criteria numbered and testable incl. authorization denial (5); no open decision (ADR 0001 accepted); no secrets or personal data.
