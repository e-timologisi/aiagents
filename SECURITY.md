# Security policy

## Supported versions

Only the latest release (and `main`) receives fixes.

## Reporting a vulnerability

Use GitHub private vulnerability reporting: open the **Security** tab of this repository and choose **Report a vulnerability**. Please do not open a public issue, discussion or pull request for security problems, and never include secrets, tokens or personal data in any report.

The maintainer is a single person; reports are handled on a best-effort basis, without a guaranteed response time.

## Scope

In scope:
- The kit's scripts (`scripts/`, `core/scripts/`). They run locally on your machine with your permissions and write files into the target repository you choose.
- Prompt-injection risks in agents, skills and prompts (for example instructions that could make an agent leak data or run unintended commands).
- Over-permissive agent permissions or tool lists generated by `sync-agents.py` or shipped in agent sources.
- Workflows and templates under `.github/` and `core/github/`.

Out of scope:
- Behaviour of third-party tools (OpenCode, VS Code, GitHub Copilot, AI models) themselves.
- Projects that installed the kit and then changed it.

Agents act with the permissions you give them. Review agent permissions before use and never give agents production credentials.
